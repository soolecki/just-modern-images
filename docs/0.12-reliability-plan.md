# Just Modern Images 0.12 reliability plan

Version 0.12 is a reliability release based on private fleet telemetry from
seven WordPress installations. Its purpose is to make background conversion
self-healing across ordinary hosting, WordPress Multisite, IIS/FastCGI and
shared SMB storage without adding day-to-day configuration.

## Evidence from the test fleet

- A 2,637-image library completed its capability probe and scheduled a scan,
  while frequent cron requests were observed, but the worker never ran. A due
  scan must therefore be claimable directly by a cron request even when the
  original single event is lost or not dispatched.
- On one Multisite installation, a temporary encoder circuit breaker caused
  1,177 images to be recorded as skipped. Temporary infrastructure state must
  never become a terminal per-image result.
- Another site in the same Multisite recovered after a fresh capability probe,
  proving that paused work can be resumed safely.
- A site with only AVIF paused continued producing WebP. A partial format
  outage must not stop a healthy format.
- CLI and long-running LiteSpeed workers consistently stop at the fixed
  20-second default despite having substantially larger execution budgets.
- Immutable publishing is safe in principle, but concurrent creates, Windows
  path length and transient SMB copy failures need explicit handling.

## Product behaviour

The settings screen remains simple. While a queue is active it shows a clear
"Processing images" state and an indeterminate animated bar. The existing
percentage continues to describe completed library work. Animation is purely
informational, respects reduced-motion preferences and does not imply that a
stalled worker is healthy.

The plugin continues to preserve original JPEG and PNG files. A failed or
paused modern format never replaces a working original or a previously valid
modern variant.

## Queue and cron guarantees

1. Every queued or running library scan has a recoverable next action.
2. During a WordPress cron request, a missing or due scan may be claimed and
   executed directly instead of waiting for another single event.
3. A dormant installation with eligible media can recreate its first scan.
4. A worker stops before PHP, IIS/FastCGI or memory limits are approached.
5. Servers with at least a minute of safe execution time may use up to 45
   seconds, while 30-second hosts keep the conservative 20-second budget.
6. If all formats are temporarily paused, the scan keeps its cursor and waits
   until the earliest safe retry. It does not sweep the library into `skipped`.
7. If one format remains available, processing continues for that format.

## Encoder health

The circuit breaker represents an encoder or environment outage, not one bad
source file. Failures are aggregated per attachment and format. A single image
with many WordPress sizes counts once, and a successful fresh encode resets the
recent failure streak. Decode and storage failures do not disable an encoder.

The 0.12 data migration starts one resumable scan so items incorrectly marked
as skipped by older circuit-breaker behaviour are reconsidered.

## Multisite model

- Quality, queue state, attachment metadata and reporting consent remain
  isolated per site.
- Network activation initializes every existing site; network deactivation
  removes scheduled work from every site.
- Sites created after network activation initialize automatically through the
  current WordPress site-initialization hook.
- Telemetry includes pseudonymous network identity plus numeric site and
  network IDs, allowing related sites to be grouped without sharing media data.
- Cron diagnostics explicitly remain per site. A network cannot be considered
  healthy merely because cron visits its main site.

## IIS, Windows and SMB storage

- Generated names are short, token-based and remain in the source directory,
  avoiding filename-component growth and preserving the correct public upload
  URL.
- Temporary names are short and unique.
- Publishing accepts an identical file won by another worker as success.
- Copy and verification use a small bounded retry for transient sharing or SMB
  visibility delays.
- Storage-related warnings receive storage reason codes and do not trip the
  encoder circuit breaker.
- IIS is conservatively capped even when PHP reports an unlimited execution
  time, because FastCGI has its own request and activity timeouts.

## Observability

- Heartbeats carry the current library, queue and format snapshot instead of
  synthetic zeroes.
- Queue recovery time and count are visible locally and included in activity
  snapshots.
- Multisite reports expose network grouping fields only after the existing
  explicit reporting consent.
- Stable reason codes distinguish scheduling, encoder, source, memory and
  storage failures.

## Verification matrix

- Unit tests: due-cron recovery, dormant recovery, pause handling, adaptive
  budgets, circuit-breaker aggregation, concurrent publishing and Multisite
  activation/deactivation isolation.
- Static checks: PHP syntax, WordPress Coding Standards and production ZIP
  contents.
- Manual fleet checks: first worker run, progress indication, capability pause
  and recovery, mapped-domain Multisite cron, IIS/FastCGI timeout safety and an
  uploads directory hosted on SMB.
